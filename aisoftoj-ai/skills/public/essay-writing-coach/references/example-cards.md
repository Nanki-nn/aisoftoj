# 范文结构卡

以下卡片只保存原创抽象结构，不包含范文原文或项目事实。

## 卡片：架构技术

- source IDs: `user-microservices-20260824`
- 适用题型：微服务、SOA 等架构技术的选择与应用。
- 结构骨架：现状问题；技术特点；选型与迁移；关键治理；问题和收益。
- 论证链：单体耦合或迭代压力；服务边界与通信决策；注册发现、容错和部署；运维成本与治理；运行效果。
- 可迁移写法：让每个技术机制对应一个项目约束和一个验证结果。
- 风险与修正：不要宣称微服务天然高可用；避免只列特点；补充数据一致性、观测和故障治理。

## 卡片：架构风格

- source IDs: `user-architecture-style-20260824`
- 适用题型：分层、调用返回、事件驱动等架构风格。
- 结构骨架：候选风格；质量约束；选型；构件或层次映射；交互过程；效果。
- 论证链：系统复杂度与质量目标；为何选择该风格；各构件职责和依赖；真实请求路径；权衡结果。
- 可迁移写法：使用一次端到端业务流程证明各层并非只有名称。
- 风险与修正：不要把 MVC 与所有架构风格混为一谈；说明跨层调用限制和性能代价。

## 卡片：系统建模

- source IDs: `user-modeling-methods-20260825`
- 适用题型：结构化、面向对象、原型和 UML 建模。
- 结构骨架：候选方法比较；项目特征；选型；分析建模；设计建模；效果。
- 论证链：复杂业务与迭代需求；选择面向对象或其他方法；功能、数据、行为模型；模型如何指导设计；缺陷发现与沟通效果。
- 可迁移写法：每提到一种图或模型，就说明产出对象、使用者和解决的问题。
- 风险与修正：核对包含与扩展等模型关系；避免把分析类、设计类和架构分层随意等同。

## 卡片：质量属性

- source IDs: `user-availability-20260825`
- 适用题型：可用性、性能、安全性等质量属性设计。
- 结构骨架：质量场景与指标；分层策略；机制；故障或压力过程；验证；不足。
- 论证链：明确目标；数据层、业务层、展示层的策略；检测和恢复；压测或演练；指标结果。
- 可迁移写法：将技术名称扩展为采用原因、工作机制、故障处理和质量贡献。
- 风险与修正：检查恢复指标冲突；CDN 不代表全业务可用；微服务不自动带来容错；产品名不能代替实施证据。

## 卡片：ABSD

- source IDs: `user-absd-20260825`
- 适用题型：基于架构的软件设计方法及应用。
- 结构骨架：六阶段概览；选择重点阶段；阶段问题；活动和工具；实施步骤；效果与演化。
- 论证链：在架构需求中追踪需求与构件；在架构复审中评估质量属性；在架构演化中管理需求变化；用产物和评审结果证明效果。
- 可迁移写法：使用“问题、阶段活动、方法工具、步骤、效果”组织每个实践段。
- 风险与修正：不要平均展开所有阶段；阶段名称、活动和实际项目产物必须对应。

## 卡片：开发模型

- source IDs: `user-development-models-20260825`
- 适用题型：软件开发模型比较、选择和应用。
- 结构骨架：候选模型；项目特征；选型依据；阶段实践；实施效果；复盘。
- 论证链：需求、规模和风险分析；选择 UP 或其他模型；按阶段说明活动与产物；展示风险降低和交付效果。
- 可迁移写法：先比较候选模型，再证明所选模型如何适配项目，而不是先定结论。
- 风险与修正：UP 要体现迭代、用例、架构和风险；避免“敏捷只适合小团队”等绝对判断。

## 卡片：通用写作框架

- source IDs: `user-writing-framework-20260824`
- 适用题型：所有需要先规划篇章的软考高级论文。
- 结构骨架：摘要；项目背景；理论回应；实践论证；结尾。
- 论证链：题干覆盖；项目底稿；一总若干分；结果、不足和改进。
- 可迁移写法：固定项目事实可以复用，论点、技术与问题必须随题干调整。
- 风险与修正：篇幅范围只是经验建议；不要让模板覆盖题干；不要把范文经历改写成自己的项目。
