# 答题会话统一退出守卫设计

## 背景

答题页内部的“首页”按钮会先确认并暂停会话，但全局导航、浏览器后退、刷新和关闭标签页会绕过该流程。后端因此没有记录暂停时间，恢复答题时会把离开期间计入用时。

## 目标

- 未交卷的答题会话通过任何方式离开时都先提示用户。
- 取消离开后继续答题和计时。
- 确认站内离开时，先暂停会话并停止本地计时，再执行原跳转。
- 刷新、关闭标签页或跳往站外时显示浏览器原生提示，并在页面卸载时尽力发送暂停请求。
- 正常交卷、已完成试卷和暂停请求失败时保持现有业务语义。

## 方案

在 `ExamSession` 内建立统一离开守卫：

1. 使用 React Router 的导航阻止器拦截所有站内路由变化，包括全局导航和浏览器后退。
2. 所有站内离开入口复用现有 `AlertDialog`。用户取消时重置被阻止的导航；用户确认时调用 `onBackToConfig` 的暂停能力，然后继续原目标导航。
3. 使用 `beforeunload` 触发浏览器原生提示；使用 `pagehide` 在真正卸载时发送带 `keepalive` 的暂停请求。取消原生提示不会触发暂停。
4. 增加退出状态作为计时器启停条件，避免用户确认后、暂停请求完成前继续增长。
5. 正常交卷前关闭离开守卫，避免结果页跳转被误拦截。

## 接口边界

`ExamSession` 不直接拼接认证信息或 API 地址。由 `App` 传入普通暂停回调和卸载阶段的暂停回调；本地 mock 会话只需清理本地状态，不发后端请求。

## 失败处理

- 站内暂停失败：保留在答题页，显示错误并恢复计时，允许重试。
- 页面卸载暂停失败：浏览器不允许阻塞离开，不打断卸载流程；后端仍以最近成功暂停或交卷时间为准。
- 连续点击确认：退出按钮禁用，避免重复请求。

## 验证

- 单元测试覆盖站内导航的确认、取消、暂停失败和正常交卷放行。
- 测试 `beforeunload` 仅在未完成会话中注册，并验证 `pagehide` 调用卸载暂停回调。
- 运行前端测试、类型检查和构建。
