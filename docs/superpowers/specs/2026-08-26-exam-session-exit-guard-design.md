# 答题会话统一退出守卫设计

## 背景

答题页内部的“首页”按钮会先确认并暂停会话，但全局导航、浏览器后退、刷新和关闭标签页会绕过该流程。后端因此没有记录暂停时间，恢复答题时会把离开期间计入用时。

## 目标

- 未交卷的答题会话通过站内导航离开时都先提示用户；刷新、关闭和站外跳转在浏览器允许时显示原生提示。
- 取消离开后继续答题和计时。
- 确认站内离开时，先暂停会话并停止本地计时，再执行原跳转。
- 刷新、关闭标签页或跳往站外时显示浏览器原生提示，并在页面卸载时尽力发送暂停请求。
- 正常交卷、已完成试卷和暂停请求失败时保持现有业务语义。

## 方案

在 `ExamSession` 内建立统一离开守卫：

1. 将入口从声明式 `BrowserRouter` 轻量迁移到 `createBrowserRouter` 与 `RouterProvider`，使 React Router 7 的 `useBlocker` 可用；现有 `App` 路由表保持不变。测试使用 `createMemoryRouter` 数据路由环境。
2. 使用 `useBlocker` 拦截所有站内路由变化，包括全局导航和浏览器后退。答题页自身“首页”按钮改为正常导航到 `/papers`，由同一守卫处理。
3. 所有站内离开入口复用现有 `AlertDialog`。用户取消时重置被阻止的导航；用户确认时先调用无导航副作用的 `onPause`，清理当前会话，再由 `blocker.proceed()` 执行原目标导航。
4. 使用 `beforeunload` 触发浏览器原生提示；使用 `pagehide` 在真正卸载时发送带 `keepalive` 的暂停请求。浏览器可能因无用户激活、移动端终止或网络中断而不显示提示或未送达请求，因此卸载暂停是尽力而为，不能作为强一致保证。
5. `pageshow` 检测 BFCache 恢复；若 `event.persisted` 为真，则重新获取并恢复会话，以后端调整后的 `startTime` 替换本地会话，再恢复计时。
6. 增加退出和交卷状态作为计时器启停条件，避免确认操作完成前继续增长。
7. `onCompleteExam` 改为可等待且返回成功状态。组件同步进入“正在交卷”状态并暂停本地计时；成功后使用一次性放行标志允许结果页导航，失败则恢复守卫与计时。手动交卷和倒计时自动交卷共用该流程。

## 接口边界

`ExamSession` 不直接拼接认证信息或 API 地址。由 `App` 传入以下回调：

- `onPause(): Promise<void>`：仅暂停后端会话，不导航。
- `onPauseOnPageHide(): void`：使用带认证头的 `fetch(..., { method: 'PATCH', keepalive: true })` 尽力暂停。
- `onResumeAfterPageShow(): Promise<void>`：重新获取并恢复会话。
- `onCompleteExam(): Promise<boolean>`：明确通知组件交卷是否成功。

本地 mock 会话的暂停和恢复只更新本地状态，不发后端请求。确认站内离开后由 `App` 提供的清理回调清除当前会话，但不得改变路由。

## 失败处理

- 站内暂停失败：保留在答题页，显示错误并恢复计时，允许重试。
- 页面卸载暂停失败：浏览器不允许阻塞离开，不打断卸载流程；后端仍以最近成功暂停或交卷时间为准。
- 连续点击确认：退出按钮禁用，避免重复请求。
- BFCache 恢复失败：保留守卫和停止状态，提示用户重试恢复，避免在错误时间基准上继续计时。
- 交卷失败：恢复退出守卫和计时，保留当前答案。

## 验证

- 使用数据路由测试环境覆盖站内导航的确认、取消、暂停失败和正常交卷放行。
- 测试 `beforeunload` 仅在未完成会话中注册，并验证 `pagehide` 调用卸载暂停回调以及 BFCache `pageshow` 恢复。
- 运行 `npm test` 和 `npm run build`。项目当前没有独立 TypeScript 配置或 `typecheck` 命令，不虚构额外校验。
