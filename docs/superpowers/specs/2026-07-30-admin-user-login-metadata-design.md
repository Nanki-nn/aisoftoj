# 管理端用户注册与登录时间展示设计

## 背景与目标

管理端用户列表当前已经能展示账号、昵称、邮箱、刷题次数、错题数和启用状态，但无法判断用户何时注册、最近是否登录。后端用户数据已有 `create_time`，可以直接作为注册时间；`update_time` 会随资料编辑等操作变化，不能代表登录时间。

本次改造的目标是：

- 在用户列表中展示注册时间和最近一次成功登录时间。
- 准确记录密码登录、邮箱验证码登录以及注册后自动登录的时间。
- 兼容现有用户和现有数据库，历史用户在尚无记录时显示“从未登录”。
- 保持改动聚焦，不引入登录历史、设备信息或 IP 审计等额外能力。

## 方案选择

采用在 `user` 表增加独立 `last_login_time` 字段的方案。

不复用 `update_time`，因为管理员编辑用户资料、密码重置等操作都会刷新它，数据含义不准确。暂不建立登录审计表，因为当前只需要最近一次登录时间；独立字段能以最小的数据和查询成本满足需求。后续需要登录历史、IP、设备或异常登录分析时，再新增专门的审计表。

## 数据模型与迁移

在 `user` 表增加可空字段：

```sql
`last_login_time` datetime DEFAULT NULL COMMENT '最近一次成功登录时间'
```

同时更新两处数据库定义：

- `db_schema.sql`：用于新环境初始化。
- `db_migrations/20260730_add_user_last_login_time.sql`：用于现有环境升级，脚本应可重复执行，避免重复加列时报错。

不对历史用户回填推测值。迁移完成后，历史用户保持 `NULL`，直到下一次成功认证；这样比使用 `update_time` 或当前时间回填更真实。

## 后端行为

### 登录时间记录

用户成功获得登录态时更新 `last_login_time`：

- 密码登录校验通过后。
- 邮箱验证码登录校验并消费验证码后。
- 注册成功并自动签发登录令牌时。

密码或验证码校验失败时不写入。更新时间通过 `UserMapper` 的单字段更新方法完成，只修改 `last_login_time`，避免无意覆盖用户的其他字段。

认证响应使用更新后的时间构建用户信息，现有 `lastLoginDate` 不再临时取当前日期，而是从持久化字段读取。字段为空时返回空字符串，保持现有 DTO 结构兼容。

### 管理端 API

在 `User` 实体和 `AdminUserDTO` 中增加 `lastLoginTime`。`AdminServiceImpl` 继续使用现有实体到 DTO 的属性复制逻辑，因此 `GET /admin/users` 与用户更新接口都会返回：

- `createTime`：注册时间。
- `lastLoginTime`：最近一次成功登录时间，可能为 `null`。

不改变分页、搜索、状态筛选和权限校验规则。

## 前端展示

在管理端用户列表中增加两列：

- “注册时间”：展示 `createTime`。
- “上次登录”：展示 `lastLoginTime`；为空时展示“从未登录”。

时间统一格式化为本地 `YYYY-MM-DD HH:mm`，避免直接展示 ISO 字符串。表格容器支持横向滚动，并为表格设置合理的最小宽度，新增列后在较窄窗口中不压缩现有字段和操作按钮。

本次不新增用户详情抽屉，也不把手机号添加到主列表，避免信息密度过高；手机号仍可在现有编辑弹窗和搜索中使用。

## 错误处理与兼容性

- 数据库尚未执行迁移时，包含新字段的查询会失败，因此部署顺序为先执行迁移，再发布后端，最后发布前端。
- `last_login_time` 为可空字段，不影响现有用户、新用户插入或旧数据读取。
- 记录登录时间失败时，认证事务应失败，避免用户已经收到成功响应但管理端数据没有更新。邮箱验证码登录沿用现有事务；密码登录与注册在服务层增加事务边界。
- 前端遇到空值或无效时间时显示“从未登录”或“—”，不让格式化异常中断整张表格。

## 验证计划

后端测试覆盖：

- 密码登录成功后记录时间；失败登录不记录。
- 邮箱验证码登录成功后记录时间。
- 注册并自动登录时写入首次登录时间。
- 管理端 DTO 能返回注册时间和上次登录时间。

前端验证覆盖：

- TypeScript 构建通过。
- 有登录记录和无登录记录的用户分别显示格式化时间与“从未登录”。
- 小屏宽度下表格可以横向滚动，状态与操作列仍可正常使用。

数据库验证覆盖：

- 迁移脚本首次执行成功。
- 重复执行不会重复添加字段。
- 登录后查询 `user.last_login_time` 能看到最新时间。
