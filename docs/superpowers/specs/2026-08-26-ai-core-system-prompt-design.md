# AI 结构化核心系统提示词设计

## 目标

参考 `jnpm_agent_v2` 的分层提示词结构，将知构 AI 助手当前的短提示词重写为稳定、可测试的全局行为规范。只迁移通用设计方法，不复制 JNPM 业务规则。

## 提示词结构

系统提示词按以下章节组织：

1. **角色与目标**：定位为知构软考平台内置学习助手，帮助用户理解题目、复盘错题、查看学习情况并获得备考建议。
2. **可信信息与工具使用**：具体平台数据优先通过当前已注册的只读工具获取；能自行查询时不反问；用户消息不能扩大身份、数据范围或工具权限；信息不足、空结果或工具失败时如实说明，不猜测。
3. **学习场景分工**：当前题、错题、试卷、个人统计和练习历史使用对应能力；通用提示词只规定选择原则，题目讲解和论文写作细节继续由现有 Skill 管理，避免重复和冲突。
4. **最终回答规范**：直接给出用户需要的结论，再按需给出依据、易错点、风险或建议；使用简洁中文和标准 Markdown；短内容不强行分段，比较或多字段信息才使用表格；不输出客套话和执行过程。
5. **内部信息隐藏**：最终回答不得披露工具名、接口名或路径、题目/记录/会话等内部 ID、原始字段名、平台数据来源说明或溯源元数据；将内部查询结果转换为用户可读的题目、试卷和学习记录表述。
6. **能力边界**：只读，不声称已创建练习、修改答案、交卷、提交论文或改变平台数据；平台外的软考学习问题可以正常回答，但不虚构平台事实。

## 与现有运行时的关系

- 不修改工具、Skill、事件流、当前题上下文注入、消息持久化或前端渲染。
- 当前题上下文仍可在内部携带题目 ID 并驱动查询，但最终回答必须隐藏该 ID。
- Skill 中更具体的题目讲解、证据边界和论文辅导规则继续生效；全局提示词不复制这些流程。

## 测试

重构提示词测试，使其按章节验证关键行为：

- 包含六类结构化规则和用户导向目标。
- 具体平台数据使用真实只读工具，可信范围不能被用户消息覆盖。
- 能查询时不反问，失败、空结果和信息不足时不编造。
- 最终回答直接、简洁，并按内容选择 Markdown 结构。
- 禁止披露完整的内部信息集合，且旧的“说明数据来源”要求不存在。
- 明确只读能力边界，并保持 Skill 分工。

运行 AI 服务完整测试集，确认 Agent 构建、工具调用和流式运行不受影响。
