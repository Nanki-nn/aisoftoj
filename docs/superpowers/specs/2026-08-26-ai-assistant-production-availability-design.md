# AI 助手线上未开放提示设计

## 背景

当前生产前端包含 AI 助手面板，但生产环境尚未部署 `/api/ai/*` 服务。面板初始化和发送消息会收到 404，并向用户展示技术性错误“AI 服务请求失败 (404)”。

## 目标

- 生产环境明确提示“AI 助手线上请求暂未开放”。
- 未开放时不发起 AI 初始化、历史记录或消息请求。
- 保留 AI 助手入口和面板，便于展示功能并在服务开放后快速启用。
- 本地开发和已配置环境继续支持现有 AI 联调流程。

## 方案

新增 Vite 构建变量 `VITE_AI_ASSISTANT_ENABLED`，并在 `src/lib/aiAvailability.ts` 中集中解析，导出 `AI_ASSISTANT_ENABLED`：

- 值为 `true`：所有模式开启。
- 值为 `false` 或其他无效非空值：关闭。
- 未设置：仅 `import.meta.env.DEV` 开启，生产关闭。

解析必须比较字符串值，不能依赖字符串 truthy 行为。同步补充 Vite 环境变量类型声明。

AI 面板读取统一的可用性常量。不可用时：

- 面板展示中性提示“AI 助手线上请求暂未开放”。
- 使用独立的不可用视图，展示带 `role="status"` 的中性提示。
- 快捷提问、输入框、发送、历史、新建会话、重试和停止等请求型控件全部使用原生 `disabled`，或在不可用状态隐藏无意义控件。
- 输入框展示不可用占位文案，不自动聚焦，不响应 Enter 提交，并提供明确的禁用样式和光标。
- 跳过会话初始化及所有 URL 匹配 `/api/ai/` 的请求；论文批改等其他 AI API 不在本开关范围内。
- 不使用红色错误样式，避免把预期的产品状态表现成故障。

现有 `agentAvailable` 表示路由是否允许展示面板，需重命名为 `agentVisibleOnRoute` 以避免和服务可用性混淆。路由可见性继续控制面板挂载，`AI_ASSISTANT_ENABLED` 只控制 AI 服务行为；支持面板的路由仍保留入口和面板。

## 数据流

1. Vite 在构建时注入开关，集中解析器计算最终可用性。
2. 面板调用 `useAIConversation({ active: isOpen, available: AI_ASSISTANT_ENABLED })`，将面板打开状态与服务可用性分开。
3. Hook 在初始化前检查可用性，并守卫发送、重试、会话选择、停止、新建会话等所有公开请求动作；从可用变为不可用或面板关闭时，中止并作废进行中的任务。
4. `aiApi.ts` 在普通请求和 SSE 两条 `fetch` 路径前增加防御性开关检查，防止未来调用方遗漏守卫。
5. 面板依据不可用状态渲染提示并禁用或隐藏请求型控件。

## 测试

- 解析器单元测试覆盖开发/生产下的未设置、`true`、`false` 和无效值。
- Hook 测试在面板激活但服务关闭时调用所有返回动作，并断言每个 AI API mock 均为零调用。
- API 层测试断言服务关闭时在 `globalThis.fetch` 前终止，包括普通请求和 SSE。
- 面板交互测试验证提示文案、原生禁用状态、不可用占位符和键盘提交无效。
- 开启状态回归测试验证初始化和发送仍正常。
- 为组件交互测试加入 `@testing-library/react`、`@testing-library/user-event` 和 `jsdom`，配置 Vitest 测试环境。
- 生产构建冒烟测试在未设置开关时验证产物默认关闭，避免环境污染。

## 部署

`VITE_*` 会编译进静态产物，修改服务器运行时环境变量不会改变已部署行为。部署模板不设置该变量或显式设为 `false`，并注意 shell 环境变量和 `.env*` 文件可能覆盖默认值。未来服务开放时必须以 `VITE_AI_ASSISTANT_ENABLED=true` 重新构建并发布前端。

发布前检查构建产物展示未开放状态，并在浏览器 Network 中确认没有 `/api/ai/*`。保留本次关闭状态的静态产物。若线上仍产生 AI 请求、提示缺失或控件可交互，立即恢复上一份已确认关闭的前端目录；如使用 CDN，还需同步回滚或清理缓存。回滚后复查提示、禁用控件和零 AI 请求。
