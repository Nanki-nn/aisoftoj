# QQ 交流群二维码悬浮入口设计

## 背景

知构软考桌面端顶部导航目前依次展示考试倒计时、GitHub Star 和用户入口。需要在 GitHub Star 与用户入口之间增加 QQ 交流群入口，用户悬浮后可扫码加入群聊。

用户已选择视觉方案 A：标准信息卡。

## 目标

- 在桌面端顶部导航的 GitHub Star 与用户头像或登录按钮之间增加一个群聊图标。
- 鼠标悬浮或键盘聚焦图标时显示 QQ 群二维码卡片。
- 卡片清楚说明入口用途，并保证二维码可扫描。
- 保持现有导航高度、间距、玻璃态风格和响应式行为。

## 非目标

- 不在移动端显示 QQ 群入口。
- 不增加群号复制、跳转 QQ、加群统计或后台配置功能。
- 不修改现有用户菜单、GitHub Star、考试倒计时或移动端抽屉。
- 不修改 `src/components/ui/` 下的基础组件。

## 交互与布局

### 入口

- 入口位于 `AppHeader` 中 GitHub Star 之后、用户头像或“登录 / 注册”按钮之前。
- 仅在 `lg` 及以上断点显示，移动端隐藏。
- 使用 40×40 像素的 ghost 风格图标按钮，图标采用 `lucide-react` 的群聊语义图标。
- 默认使用浅色中性文字，悬浮时出现浅蓝背景和蓝色图标，与现有蓝色主色保持一致。
- 按钮提供 `aria-label="加入 QQ 交流群"` 和清晰的键盘焦点环。

### 悬浮卡片

- 复用现有 Shadcn/Radix `HoverCard`，不自行实现悬浮状态机。
- 鼠标悬浮和键盘聚焦均可打开。
- 使用 `180ms` 打开延迟和 `120ms` 关闭延迟，避免鼠标经过导航时误触，同时允许鼠标从触发器移到卡片。
- 卡片显示在触发器下方，向右对齐，避免覆盖用户头像并减少超出视口的概率。
- 卡片宽度约 240 像素，圆角约 16 像素，使用白色背景、浅灰边框和柔和阴影。
- 内容依次为：
  1. 标题“加入 QQ 交流群”；
  2. 说明“扫码交流备考经验”；
  3. 约 190×190 像素的二维码。
- 卡片不包含点击操作和额外链接。

## 组件边界

- 新建 `CommunityQrHoverCard` 业务组件，封装触发器、HoverCard 和二维码内容。
- `AppHeader` 只负责在指定位置渲染该组件，避免继续扩大导航组件职责。
- 复用现有 `Button` 和 `HoverCard`，不修改 Shadcn UI 基础组件。

## 二维码资源

- 将已确认的 QQ 群二维码保存为 `src/assets/qq-community-qr.png`，并通过 TypeScript import 引用。
- 由 Vite 构建管线生成带内容哈希的生产资源，避免依赖外部图片地址。
- 图片提供 `alt="QQ 交流群二维码"`。
- 保持原始长宽比，不裁剪二维码有效区域，不做压缩性重绘或颜色处理。
- 当前原始资源尺寸为 790×862，已通过 ZXing 解码为 `https://qm.qq.com/q/XkTGjZRJgA`；实现时复制原文件字节，不重新编码。

## 错误处理

- 图片资源由构建期解析，资源缺失应直接导致生产构建失败，而不是线上静默请求第三方地址。
- 若浏览器无法显示图片，替代文本仍应说明这是 QQ 交流群二维码。
- HoverCard 不保存业务状态，不涉及 API 请求或服务端错误。

## 验证

- 前端现有 Vitest 测试全部通过。
- 生产构建成功，二维码被打包为本地哈希资源。
- 在桌面宽度验证入口处于 GitHub Star 与用户入口之间。
- 验证鼠标悬浮、移入卡片、移出卡片和键盘 Tab 聚焦行为。
- 验证二维码能被 QQ 客户端扫描识别。
- 在小于 `lg` 的视口确认入口完全隐藏，移动端抽屉不新增入口。
- 验证登录和未登录两种 Header 状态均没有拥挤或跳位。

## 验收标准

- 桌面端只显示一个群聊图标，不显示常驻文字。
- 悬浮或聚焦后展示用户选定的标准信息卡。
- 二维码清晰、可扫描，卡片不遮挡用户菜单的主要操作。
- 移动端不显示该入口。
- 现有 Header 功能、测试和生产构建不回归。
