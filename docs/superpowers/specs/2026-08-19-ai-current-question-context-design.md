# AI 当前题目上下文设计

## 目标

用户在答题页打开全局 AI 助手并发送消息时，助手应可靠识别发送瞬间正在查看的题目，同时保持用户输入为原始文本。题目内容由 AI 服务通过现有只读平台工具读取，不由浏览器拼接进消息。

## 范围

- 仅为 AI run 增加可选的当前题目上下文。
- 第一版上下文只包含结构化 `question_id`，不携带题干、答案、页签名称或路由字符串。
- 非答题页、无法解析题目 ID、以及没有当前题目的页面继续按现有无上下文方式工作。
- 不改变会话历史展示，不修改用户消息正文，不新增写工具。

## 客户端契约

前端在每次实际发送或重试消息时读取最新页面状态，而不是在 AI 面板首次打开时缓存题目。`POST /api/ai/threads/{thread_id}/runs` 请求扩展为：

```json
{
  "message": "帮我分析一下",
  "context": {
    "question_id": 123
  }
}
```

`context` 和 `question_id` 均为可选。前端只发送正整数 ID。重试复用原 run 的幂等键时，服务端仍以首次成功创建的 run 快照为准；客户端之后的页面变化不得改变已创建 run 的语义。

## 页面题目解析

前端提供一个纯函数，从当前 URL 与路由状态解析题目 ID。答题会话页以 URL 查询参数 `questionId` 为最高优先级；若 URL 未显式指定，则由答题页在当前题目变化时把当前 ID发布到轻量页面上下文。论文编辑页可从路径参数解析 ID。其他页面返回空上下文。

AI 面板调用发送函数时才读取该上下文，因此面板常驻、用户切题后发送、以及从其他页面返回答题页都能拿到最新值。用户输入框和历史消息只保存用户原文。

## 服务端运行快照

AI API 对 `context.question_id` 做严格正整数校验，并在创建 run 的同一事务中把规范化上下文存入 run。运行 worker 从持久化的 run 快照恢复上下文，而不依赖可变的浏览器状态或进程内全局变量。

数据库为 `ai_run` 增加可空的 `question_id` 列。单字段列便于约束、查询和后续排障，避免为当前单一需求引入无约束 JSON。API 的 run 响应不需要回显该字段，防止扩大不必要的公开契约。

## Agent 行为

`AgentContext` 增加可选 `question_id`。当它存在时，系统在模型输入中加入可信页面上下文，并明确要求：涉及“这题、当前题、这个选项”等指代或题目讲解时，先调用 `get_question(question_id)`，再依据工具结果回答。

页面上下文仅提供定位线索，不等于题目内容，也不绕过平台权限。`get_question` 继续使用当前用户 bearer token 调用后端内部接口；无权限、题目不存在或平台暂时不可用时，沿用现有工具错误处理，模型不得猜测题目。

## 安全与隐私

- 浏览器不能提交题干、答案、解析或任意系统提示作为可信上下文。
- 服务端只接受已定义的 `question_id` 字段，拒绝额外上下文字段。
- 用户消息正文与结构化上下文分开持久化和传递，避免上下文污染对话记录。
- 所有取题仍经过后端内部接口和用户身份校验。

## 错误处理

- 非法 `question_id`：请求校验失败，返回 422，不创建消息或 run。
- 没有题目上下文：正常创建 run，行为与现有版本一致。
- 同一幂等键重复请求但上下文不同：返回首次创建的 run，不覆盖快照。
- worker 重启或延迟执行：从 run 记录读取快照，保证发送时语义稳定。

## 测试

- 前端单元测试覆盖 URL/页面上下文解析、发送时读取最新题目、无题目时省略 context、重试不污染消息正文。
- AI API 测试覆盖合法/缺省/非法上下文、持久化快照、幂等重放不覆盖快照。
- Agent 测试覆盖 `question_id` 进入运行上下文和系统提示；现有 `get_question` 授权测试继续证明取题使用用户 token。
