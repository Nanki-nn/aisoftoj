# AI 当前题目上下文设计

## 目标

用户在答题页打开全局 AI 助手并发送消息时，助手应可靠识别发送瞬间正在查看的题目，同时保持用户输入为原始文本。题目内容由 AI 服务通过现有只读平台工具读取，不由浏览器拼接进消息。

## 范围

- 仅为 AI run 增加可选的当前题目上下文。
- 第一版上下文只包含结构化 `question_id`，不携带题干、答案、页签名称或路由字符串。
- 非答题页、无法解析题目 ID、以及没有当前题目的页面继续按现有无上下文方式工作。
- 不改变会话历史展示，不修改用户消息正文，不新增写工具。

## 客户端契约

前端在每次实际发送或重试消息时读取最新页面状态，而不是在 AI 面板首次打开时缓存题目。`POST /api/ai/threads/{thread_id}/runs` 请求扩展为：

```json
{
  "message": "帮我分析一下",
  "context": {
    "question_id": 123
  }
}
```

`context` 和 `question_id` 均为可选。前端只发送正整数 ID。AI API 使用禁止额外字段的嵌套请求模型，且 `question_id` 必须是严格整数，范围为 `1..2147483647`；字符串、布尔值、浮点数和未知字段均返回 422。`null` 或空 context 等同于没有题目上下文。重试复用原 run 的幂等键时，服务端仍以首次成功创建的 run 快照为准；客户端之后的页面变化不得改变已创建 run 的语义。

## 页面题目解析

答题会话页继续使用 URL 查询参数 `questionId` 做首次题目定位，但参数不作为发送时上下文来源。页面挂载和当前题目变化时，把实际渲染题目的 ID 发布到轻量全局页面上下文；即使用户从带参入口进入后连续切题，发送时也以当前渲染题目为准。页面卸载时清空自己发布的上下文，防止跨页面残留。论文编辑页可按同样方式从当前编辑题目发布 ID。其他页面保持空上下文。

AI 面板调用发送函数时才读取该上下文，因此面板常驻、用户切题后发送、以及从其他页面返回答题页都能拿到最新值。用户输入框和历史消息只保存用户原文。

## 服务端运行快照

AI API 对 `context.question_id` 做上述严格校验，并在创建 run 的同一事务中把规范化上下文存入 run。路由启动 worker 时只传递身份和 run 定位信息；worker 在实际执行前按 `run_id` 读取持久化题目快照，并用数据库值构造本次运行上下文，不把请求体或进程内闭包当作题目上下文真相。

新增 Alembic revision，为 `ai_runs` 增加可空 `question_id`，SQLAlchemy 模型使用 `Mapped[int | None]`，repository `create` 显式接收该值，downgrade 删除该列。单字段列便于约束、查询和后续排障，避免为当前单一需求引入无约束 JSON。部署时先执行数据库迁移再启动新应用。API 的 run 响应不需要回显该字段，防止扩大不必要的公开契约。

## Agent 行为

`AgentContext` 增加可选 `question_id`。worker 从 run 快照读取该值后，为当前 turn 注入一条不持久化的 `SystemMessage`，声明可信当前题目 ID，并明确要求：涉及“这题、当前题、这个选项”等指代或题目讲解时，先调用 `get_question(question_id)`，再依据工具结果回答。该上下文只解释本次 `input_message_id`，不得用于重新解释历史消息里的指代。

模型工具调用属于提示词约束而非服务端强制状态机；第一版不预取题目，也不拒绝未调用工具的模型输出。验收通过捕获模型输入和模拟工具调用证明指令与工具参数正确，生产效果继续由既有工具审计事件观测。

页面上下文仅提供定位线索，不等于题目内容，也不绕过平台权限。`get_question` 继续使用当前用户 bearer token 调用后端内部接口；无权限、题目不存在或平台暂时不可用时，沿用现有工具错误处理，模型不得猜测题目。

## 安全与隐私

- 浏览器不能提交题干、答案、解析或任意系统提示作为可信上下文。
- 服务端只接受已定义的 `question_id` 字段，拒绝额外上下文字段。
- 用户消息正文与结构化上下文分开持久化和传递，避免上下文污染对话记录。
- 所有取题仍经过后端内部接口和用户身份校验。

## 错误处理

- 非法 `question_id`：请求校验失败，返回 422，不创建消息或 run。
- 没有题目上下文：正常创建 run，行为与现有版本一致。
- 同一幂等键重复请求但上下文不同：返回首次创建的 run，不覆盖快照。
- worker 延迟执行：从 run 记录读取快照，保证发送时语义稳定。服务重启仍按现有策略把未完成 run 标记为 `interrupted`，不在本需求中增加续跑。

## 测试

- 前端单元测试覆盖带参入口首次定位后连续切题、卸载清理、发送时读取最新题目、无题目时省略 context、重试不把上下文拼入消息正文。
- AI API 测试覆盖合法/缺省上下文；字符串、布尔、浮点、零、负数、超上限、未知字段等非法上下文；422 不创建数据；持久化快照；幂等重放不覆盖快照。
- Agent/worker 测试覆盖 worker 从数据库字段而非调用方内存值构造 `question_id`，捕获模型输入中的本次 turn 系统消息和 `get_question` 调用参数；现有工具测试继续证明取题使用用户 token。
- 模型与迁移测试覆盖 `ai_runs.question_id` 的可空列及 Alembic upgrade/downgrade 声明。
- 回归运行前端测试、AI 服务测试及相关后端契约测试。

“用户原文”在本设计中指沿用现有首尾空白规范化后的消息正文，并保证不向其中拼接题目 ID、题干、提示词或其他页面上下文；不改变既有 trim 行为。
