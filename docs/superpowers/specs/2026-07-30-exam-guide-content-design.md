# 系统架构师备考经验内容优化设计

## 目标

使用 `/Users/bytedance/Downloads/二个月在职备考软考系统架构师，一次通过经验分享.md` 作为备考经验正文的唯一内容来源，更新 `guides/系统架构师备考经验.md`，使文章在 GitHub 中结构清晰、格式稳定，同时保留作者原有经历、方法和表达重点。

## 内容范围

- 正文只保留下载稿中的个人背景、备考资料和 8 周备考流程。
- 保留用户单独确认的“联系我”章节，复用仓库根目录的微信二维码 `img_1.png`。
- 联系方式只展示二维码和添加好友时的备注说明，删除“微信号：你的微信号”占位文本。
- 删除当前仓库版额外加入的“我觉得最有用的几个方法”和“这段备考经历和这个项目的关系”。
- 不增加下载稿之外的备考经历、成绩、建议或产品宣传内容。

## 编辑规则

- 使用文件名含义补充一级标题：“两个月在职备考软考系统架构师：一次通过经验分享”。
- 保留下载稿的章节顺序、事实信息和第一人称语气，只优化冗余表达、标点、段落和列表结构。
- 清理语雀导出的 OCR 注释、`<font>` 标签和不兼容的列表标记。
- 将颜色强调转换为 GitHub Markdown 的加粗语法，不依赖字体颜色表达重点。
- 统一明显的文字不一致和错别字，例如将网课品牌统一为“希赛”。
- 保留语雀笔记链接，并将仓库中已有图片改为相对路径引用。

## 图片处理

- 将下载稿中的两张语雀 CDN 图片保存到 `guides/`，使用能表达内容的文件名，避免外链失效。
- 下载稿引用的 `img.png`、`img_1.png`、`img_2.png` 改为同目录相对路径。
- 联系方式继续引用仓库根目录的 `img_1.png`，相对路径为 `../img_1.png`。
- 图片居中和宽度使用 GitHub 支持的简洁 HTML，补充明确的替代文本。

## 验收标准

- 指南正文信息全部来自下载稿，正文结束后只追加经确认的联系方式。
- 文档中不存在 `<font>`、OCR 注释、“你的微信号”、平台关系章节或额外方法总结。
- 所有本地图片路径均存在，两张语雀 CDN 图片不再依赖远程地址。
- 语雀笔记链接和仓库 README 中的指南链接保持有效。
- 提交只包含指南、为该指南新增的图片和本设计说明，不包含工作区其他改动。
