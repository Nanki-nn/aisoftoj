# 后端配置取消跟踪设计

## 背景

`aisoftoj-backend/src/main/resources/application.yml` 和
`application-prod.yml` 已被提交到远端仓库。默认配置包含本地数据库密码及若干开发
密钥默认值；生产配置虽然只引用环境变量，但用户要求两个文件都不再出现在 GitHub
当前版本中，并已在本地另行保存配置。

## 目标

- 从 Git 索引中移除两个后端配置文件，并生成一个聚焦提交，为 GitHub 删除它们做好
  准备。
- 保留工作区中的两个本地文件及其现有内容，不覆盖用户尚未提交的数据库端口修改。
- 为两个准确路径添加忽略规则，避免本地配置再次被误提交。
- 扫描其他已跟踪文件中的常见私钥、云访问密钥和令牌模式，报告可疑项但不显示值。

## 实施方案

先记录两个文件的摘要，然后使用 `git rm --cached` 仅取消跟踪。`.gitignore` 使用两个
精确路径，不扩大到所有 Spring 配置文件，以免未来无法提交经过脱敏的示例模板。
完成后创建只包含 `.gitignore` 和两个删除记录的聚焦提交，并验证：

1. 两个文件仍存在于本地，且摘要未变化。
2. `git ls-files` 不再包含它们。
3. `git check-ignore` 能命中新增规则。
4. 提交只包含两个删除记录和 `.gitignore` 修改。

## 安全边界

本次操作不清除旧提交中的内容，也不执行历史重写或强制推送。当前本地 `main` 包含
多项尚未发布的其他提交，因此本次不直接推送，避免把无关工作一并发布；GitHub 当前
文件树将在该聚焦提交被安全整合并推送后更新。已暴露且在其他环境复用的密码或密钥
仍需轮换。历史清理属于单独的高风险操作，未经明确授权不执行。

## 扫描策略

扫描当前已跟踪文件中的私钥头、常见云访问密钥、GitHub/OpenAI 风格令牌，以及配置
文件里的非占位敏感值。测试夹具、变量名和文档示例需要人工分类，避免把普通代码中的
`token`、`password` 字段误报为真实凭据。扫描输出仅包含文件位置和风险类型。
