# AI 执行过程与 Markdown 回答设计

## 背景

当前 AI Worker 将 Agent 每轮产生的文本片段全部累加为最终回答。调用工具前的
“我先查询、再分析”等叙述因此与结论混在一起。前端虽使用 `ReactMarkdown`，回答
容器却依赖项目未安装的 Tailwind Typography `prose` 样式，导致 Markdown 层级不
明显。

本设计参考 JNPM Agent 的轮次过滤、事件归并和过程面板机制，但不展示模型原始隐藏
思维链。

## 目标

- 工具调用前的安全操作说明进入可折叠“执行过程”，不进入最终持久化回答。
- 最终回答只保留结论、依据、风险和建议，并使用结构清晰的 Markdown。
- 实时 SSE 与刷新后的事件重放得到一致的过程区和回答区。
- 运行态不使用旋转加载图标，改用从左向右扫过的文字渐变。
- 保持现有工具摘要脱敏、只读权限和错误处理边界。

## 后端文本分流

Worker 同时消费 LangGraph 的 `messages` 与 `values` 流：

1. 只处理根 `model` 节点的 assistant 文本，忽略内部节点产生的文本。
2. 当前模型轮次的可见文本先作为 `message.delta` 实时发布，并暂存在
   `pending_model_text`。
3. 当完整 State 表明该轮包含工具调用时，从最终回答累加器中移除这段 pending
   文本；已发布事件保留，供前端归入过程区。
4. 没有工具调用的轮次保留为最终回答；Run 完成时只持久化过滤后的正文。
5. Provider 的 `reasoning_content` 与 reasoning/thinking 内容块不发布、不持久化，
   也不进入最终回答。

系统提示补充两类约束：最终回答直接给结论，不重复过程性叙述；默认使用标准
Markdown，列表、分组信息和多字段比较分别使用列表、标题和表格。

## 前端事件与状态

`RunViewState` 新增有序的过程说明。收到 `answer.delta` 时仍实时追加回答；收到
`tool.started` 时，如果回答区已有文本，则把它移动成一条过程说明、清空回答区，
再记录工具步骤。过程说明和工具步骤都保存事件序号，面板按序号交错渲染。

该归并规则同时用于实时 SSE 和历史事件重放。服务端完成后返回的 assistant Message
是最终正文，优先作为回答区内容。已有旧消息不做启发式文字切割，避免误删正常内容；
新 Run 按新协议保证分离。

## 交互与视觉

过程区位于用户问题和最终回答之间：

- 运行中默认展开，显示“正在分析”及过程说明、工具步骤。
- 完成后显示“完成 N 个步骤”并自动收起，用户可手动展开。
- 不使用 `Loader2` 等旋转动画。标题和当前步骤采用浅灰到蓝色再到浅灰的水平渐变，
  背景位置从左向右循环，形成扫光效果。
- 已完成步骤使用静态绿色对勾；失败步骤使用静态红色提示。
- `prefers-reduced-motion: reduce` 下停止扫光，回退为普通文字颜色。

最终回答是独立的浅色卡片，并为 `.markdown-body` 增加明确样式：

- `h1` 至 `h4` 的字号、间距和层级；
- 段落、无序/有序列表、引用和分隔线；
- GFM 表格的边框、表头、横向滚动；
- 行内代码和代码块的字体、背景与溢出滚动；
- 安全链接和图片的换行与尺寸约束。

继续使用 `ReactMarkdown + remark-gfm`，不启用原始 HTML 渲染。

## 错误与中断

失败、取消或服务重启时保留已产生的过程步骤和部分最终回答。未完成工具沿用现有失败
状态。终态后不继续动画；错误正文仍使用稳定错误码映射，不展示异常栈或模型内部内容。

## 测试与验证

后端测试覆盖：

- 无工具调用时文本完整进入最终回答；
- 工具调用前叙述实时发布但不进入最终持久化回答；
- 多轮工具调用只保留最后的最终回答；
- 非根模型文本与 provider reasoning 不进入用户回答。

前端测试覆盖：

- `tool.started` 将已有回答移动到有序过程说明；
- SSE 重放产生相同状态，最终 Message 不重复过程文字；
- 过程面板完成后收起且没有旋转图标；
- Markdown 标题、列表、表格和代码块生成正确元素并应用回答样式类。

最后运行 Python AI 服务测试、前端 Vitest 与生产构建，并在本地浏览器验证窄面板下的
表格横向滚动、扫光动画、自动折叠和最终回答层级。

## 非目标

- 不展示或存储模型原始隐藏思维链。
- 不为旧历史消息做基于中文关键词的危险切割。
- 不改变平台工具权限、业务 API 或数据库表结构。
