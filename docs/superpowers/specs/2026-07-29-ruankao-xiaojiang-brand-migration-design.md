# 软考小酱品牌迁移设计

## 状态

- 日期：2026-07-29
- 决策：已确认
- 当前品牌：知构软考
- 新品牌：软考小酱
- AI Agent 名称：小酱

## 背景与目标

“知构软考”具有专业感，但名称抽象、口头传播成本较高，也不便于承载一个清晰的人格化 IP。产品将长期只服务软考，不需要为跨考试品类预留抽象总品牌。因此，对外品牌统一改为“软考小酱”，未来的站内 AI Agent 使用简称“小酱”。

本次只完成品牌迁移，不实现 Agent 功能。目标是让用户在网页、邮件、文档和社区入口中看到一致的新名称，同时不改变现有业务逻辑、接口、数据和部署拓扑。

## 品牌架构

| 层级 | 名称或文案 | 使用位置 |
| --- | --- | --- |
| 主品牌 | 软考小酱 | 页头、登录页、页面标题、邮件、README、后台标题 |
| AI Agent | 小酱 | 未来的讲题、错题分析、学习报告和备考计划入口 |
| 定位语 | AI 驱动的软考刷题与学习平台 | HTML 描述、README 和对外产品介绍 |
| 品牌口号 | 你的软考备考搭子 | 营销型页面和未来 Agent 入口；不强制出现在每个页面 |
| 过渡说明 | 软考小酱（原知构软考） | 仅在 README 首段保留一个发布周期，不出现在产品主界面 |

推荐传播句为：“刷软考真题，就来软考小酱；不会的题，直接问小酱。”它是传播素材，不作为全站固定副标题。

## 迁移原则

1. 用户可见区域统一使用“软考小酱”，不再混用“知构软考”“知构软考刷题平台”或“Zhigou Prep”。
2. Agent 只称“小酱”，不使用“软考小酱 Agent”作为界面名称。
3. 保留现有蓝色视觉体系、毕业帽图标、几何标志和页面布局。本次不设计吉祥物，也不重做 Logo 图形。
4. `aisoftoj` 仓库名、GitHub 地址、Java 包名、Maven 坐标、数据库名和 API 路径都是技术标识，不随品牌改名。
5. 不直接编辑 Vite 生成的 `aisoftoj-front/build/` 内容；构建时由源文件重新生成。
6. 生产环境如果显式设置了 `MAIL_FROM_NAME`，代码默认值不会覆盖它。上线时需要同步把部署环境值改为“软考小酱”。

## 实施范围

### 1. 前端品牌常量

新增 `aisoftoj-front/src/config/brand.ts`，集中导出：

```ts
export const BRAND_NAME = '软考小酱';
export const AGENT_NAME = '小酱';
export const BRAND_DESCRIPTION = 'AI 驱动的软考刷题与学习平台';
export const BRAND_TAGLINE = '你的软考备考搭子';
```

React 组件中的品牌文案优先引用这些常量，避免 Agent 上线后再次出现名称分叉。静态 HTML、后端邮件和 Markdown 文档无法共享该模块，允许保留对应字面量。

### 2. 前端用户界面

需要更新以下露出：

- `BrandLogo.tsx`：文字标识改为“软考小酱”，视觉上保留蓝色强调，可将“小酱”作为强调部分。
- `AppHeader.tsx`：桌面端、移动端名称和无障碍标签统一改为“软考小酱”。
- `AuthPage.tsx`：登录和注册区域的完整名称统一改为“软考小酱”。
- `EssayHome.tsx`、`EssayEditor.tsx`、`EssayResult.tsx`、`EssayHistory.tsx`：旧品牌文字统一替换。
- `admin/AdminLayout.tsx`：改为“软考小酱后台”。

`LearningLanding.tsx` 的 Hero 标题“软考备考，从路径开始。”和现有介绍文案保持不变；首页通过 `AppHeader` 展示新品牌，不额外把定位语塞入 Hero。本次不新增“小酱”聊天入口，不把普通按钮改成 Agent 功能，也不改变已有导航结构。

### 3. 页面元数据与可发现性

更新 `aisoftoj-front/index.html`：

- `<html lang>` 从 `en` 改为 `zh-CN`。
- `<title>` 改为“软考小酱｜AI 软考刷题与学习平台”。
- 新增描述产品定位的 `meta name="description"`。
- 保留现有 favicon；吉祥物或新图标另立设计任务。

### 4. 认证邮件

以下后端默认值和用户可见文案改为“软考小酱”：

- `AuthEmailProperties.java` 的默认发件人名称。
- `application.yml` 与 `application-prod.yml` 的 `MAIL_FROM_NAME` 默认值。
- `SmtpAuthEmailSender.java` 的邮件主题和 HTML 标题。
- `.env.production.example` 的示例值。

验证码、有效期、安全提示和发送逻辑保持不变。

### 5. 项目与产品文档

更新当前仍承担产品说明作用的文件：

- `README.md`：标题、产品介绍、入群备注和页尾团队名；首段保留一次“原知构软考”过渡说明。
- `AGENTS.md`、`CLAUDE.md`：项目标题、产品名和示例页面标题。
- `PRD.md`：产品标题及页头品牌描述。
- `guides/系统架构师备考经验.md`：产品起源处的品牌名。
- `LICENSE`：现有产品名形式的版权署名替换为新品牌名。

`docs/superpowers/specs/` 中已经完成的设计文档属于历史决策记录，不回写旧文档中的项目名称。构建产物、未纳入版本控制的 `.superpowers/` 文件，以及被 `.gitignore` 明确排除的本地 `aisoftoj-front/README.md` 也不作为本次迁移对象。

## 数据流与兼容性

品牌名称目前不是数据库字段，也不参与 API 请求或响应。改名只影响展示字符串和邮件呈现：

1. 浏览器从前端品牌常量或 `index.html` 读取新名称。
2. 后端从 `MAIL_FROM_NAME` 读取邮件发件人名称；未配置时使用新的默认值。
3. 用户、试卷、会话、错题和认证数据不迁移。
4. 现有 URL、登录状态、本地存储键和接口调用保持不变。

因此，本次不需要数据库迁移，也不需要兼容新旧 API 版本。

## 异常与发布处理

- 如果生产环境仍显示旧邮件发件人，优先检查部署环境中的 `MAIL_FROM_NAME`，而不是修改代码逻辑。
- 如果构建目录仍出现旧名称，删除或重新生成本地构建产物；不手工修补生成文件。
- 如果第三方平台、搜索引擎缓存或旧邮件继续展示旧名称，视为外部缓存，不在应用内增加双品牌补丁。
- GitHub 仓库描述、域名、公众号和社交媒体账号属于外部平台变更，需单独确认可用性和权限后处理。

## 发布检查

1. 部署前检查生产环境是否显式配置 `MAIL_FROM_NAME`；如有，更新为“软考小酱”。
2. 部署后发送一封测试验证码邮件，确认发件人、主题和正文标题均使用新品牌。
3. 品牌改名上线 30 天后或下一个正式版本发布时（以先到者为准），移除 README 中“原知构软考”的过渡说明。
4. 外部平台名称变更不阻塞应用发布，但应单独记录仍未更新的平台和所需权限。

## 验证标准

### 自动检查

1. 运行前端测试：`cd aisoftoj-front && npm test`。
2. 运行前端构建：`cd aisoftoj-front && npm run build`。
3. 运行后端测试：`mvn -pl aisoftoj-backend test`。
4. 对版本控制内的现行源文件执行旧品牌检索，并显式排除历史设计目录 `docs/superpowers/specs/`。除 README 中唯一的过渡说明外，不应再出现“知构”或“Zhigou Prep”。建议命令：`git grep -n -E '知构|Zhigou Prep' -- ':!docs/superpowers/specs/**'`。

### 人工检查

- 首页和各业务页页头在桌面端、移动端均显示“软考小酱”。
- 登录/注册页、论文相关页面和后台标题没有旧品牌残留。
- 浏览器标签显示“软考小酱｜AI 软考刷题与学习平台”。
- 屏幕阅读器使用的页头链接标签包含新品牌名。
- 测试环境发送的验证码邮件，其发件人、主题和正文标题均显示“软考小酱”。
- README 和项目规范中的产品名与界面一致。

## 不在本次范围内

- 小酱 Agent 的产品能力、对话界面、提示词、模型选择和数据权限。
- 新 Logo、吉祥物、头像、插画、动效或整体视觉重构。
- 域名、GitHub 仓库名、包名、数据库名和 API 路径改名。
- 商标注册、公众号/视频号/小红书等账号注册。
- 将品牌扩展到软考以外的考试或学习场景。

## 完成定义

所有受版本控制的现行用户界面、邮件和产品文档已采用“软考小酱”；旧名称只允许保留在历史设计目录 `docs/superpowers/specs/` 与 README 的单次过渡说明中；生产邮件配置已检查；自动检查通过；没有业务行为、数据结构或接口变更。
