# AI 流式回答自动跟随设计

## 问题与目标

AI 回答的 `message.delta` 会实时更新 `runStates.answer`，但当前滚动 effect 只依赖
`messages` 和 `isGenerating`。流式正文增长不会触发滚动，因此回答在视口下方生成，直到
完成后刷新持久化消息才突然出现。

目标是在用户位于对话底部时实时跟随流式回答，同时尊重用户主动向上查看历史的行为。

## 状态与数据流

在 `AIAgentPanel` 内用 `useRef(true)` 维护一个不触发渲染的 `autoFollowRef`，确保首次
异步加载历史消息后默认滚到底部。滚动容器每次产生 scroll
事件时计算 `scrollHeight - scrollTop - clientHeight`：距离不超过 80px 视为仍在底部，
保持自动跟随；超过阈值则暂停。

滚动 effect 增加 `runStates` 依赖。消息、生成状态或任一 Run 的流式文本、过程步骤变化
后，如果 `autoFollowRef` 为真，将容器立即滚到最新 `scrollHeight`。流式更新使用即时滚动，
不为每个 token 排队创建平滑动画。

用户发送新消息、切换会话、新建会话或重新打开 AI 面板时重新启用自动跟随，确保新问题、
新回答和当前会话末尾进入视口；关闭面板时不滚动。用户随后主动上滚仍可再次暂停。该状态
只属于当前 UI，不写入会话或后端。`isOpen` 参与滚动 effect 的生命周期判断。

## 边界与降级

- 空容器或面板关闭时不执行滚动；
- 程序滚到底后产生的 scroll 事件会继续判定为底部，不会关闭跟随；
- 用户停在底部附近时，过程说明、工具步骤和正文流式增长都触发跟随；
- 用户上滚超过阈值后，后续 token 不抢回位置；
- 完成态持久化消息替换流式正文时沿用同一策略，不产生二次跳动；
- 不修改 SSE、Run reducer、消息分组或后端协议。

## 测试

- 底部状态下 `runStates.answer` 增长会滚到新的 `scrollHeight`；
- 用户上滚超过阈值后，新的流式 delta 不触发滚动；
- 用户重新滚回底部后恢复自动跟随；
- 发送新消息会重新启用跟随；
- 切换会话、新建会话和重新打开面板分别恢复自动跟随；
- 面板关闭期间的 `runStates` 变化不触发滚动；
- 测试中的 `runStates` mock 保持稳定引用，仅在验证流式更新时通过 rerender 显式替换；
- 前端完整 Vitest 和生产构建继续通过。
