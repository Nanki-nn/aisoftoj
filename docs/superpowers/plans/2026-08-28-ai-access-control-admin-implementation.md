# AI 助手后台访问控制实施计划

## 交付目标

把 AI 灰度名单从环境变量迁移到 MySQL，并在后台提供全局开关、AI 设置页名单管理和用户管理页快捷开关。所有权限判断由 AI 服务统一执行，管理员接口在全局关闭时仍可恢复服务。

## 实施步骤

1. **数据库与访问服务**
   - 新增 Alembic `0005`：`ai_access_config`、`ai_rollout_users`、`ai_access_audit_log`。
   - 新增 SQLAlchemy 模型与 `AiAccessControlService`，实现查询、开关、名单分页、批量状态、幂等添加/移除和同事务审计。
   - 配置表或单例缺失、数据库异常均 fail closed。

2. **AI 权限链路与管理 API**
   - 用数据库决策替换环境变量运行时名单；`capability` 只评估，业务路由强制拒绝。
   - 管理员始终可调用 access 管理 API，即使全局开关关闭。
   - 在 Run 创建以及每轮模型/工具调用前重新检查访问资格；权限丢失时 Run 失败并写稳定错误码。
   - 增加全局配置、名单分页、批量状态、添加和移除接口。

3. **Java 平台用户契约**
   - 新增仅内部可调用的管理员批量用户查询 DTO、Service 和 Controller 端点。
   - 同时验证 Service Key 与管理员 Bearer JWT，返回角色、启用和删除状态。
   - 扩展 Python PlatformClient 的模型与批量请求。

4. **后台双入口**
   - 扩展 `aiApi.ts` 的访问控制类型和请求函数。
   - AI 设置页增加全局开关、二次确认、候选用户搜索和名单分页/移除。
   - 用户管理页增加当前页批量状态读取与“AI 内测”快捷开关；管理员和禁用账号不可切换。

5. **测试与验证**
   - Python：权限矩阵、fail-closed、管理员 API、审计事务、失效账号和运行中撤权。
   - Java：双重鉴权、批量上限、返回字段和缺失 ID。
   - React：全局开关、确认、失败恢复、名单双入口同步。
   - 运行 Python、Maven、Vitest、TypeScript 和生产构建；检查迁移链及工作区差异。

6. **交付**
   - 只提交本功能和对应设计/计划文档，不包含无关改动或秘密。
   - 本次不直接修改线上数据库或部署；生产迁移与 E2E 在代码验证通过后单独执行。
